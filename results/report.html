Caveats

read before you trust a number

No platform is marked failed on this run. That's not the same as every number being equally trustworthy.

CognoDB's free tier is genuinely flaky

Bolt connections dropped mid-request at roughly a 1-in-20 to 1-in-25 rate across this project, reproduced across multiple fresh instances. The harness compensates with managed-transaction retry plus an outer batch/call retry with backoff — so CognoDB's numbers above include real retry tax, not a cherry-picked best case. That's part of why its p95s are the highest in every table.

The loader isn't idempotent

load_nodes/load_edges use CREATE, not MERGE. Interrupted test runs earlier in this project silently inflated CognoDB to 1,016,079 nodes and Aura to 197,594 (vs. the intended 126,297) before it was caught. Both instances were wiped and reloaded clean before this run — verified against dataset_info.json — but re-running the harness against a non-empty database will reproduce the bug. Not fixed in this codebase.

Neo4j Community's concurrency collapse is a resource story

10 errors at concurrency 10, 40 at concurrency 40 — every other platform shows zero at the same levels. All are Bolt transaction retry-timeouts from many threads racing to write against the same small graph inside a 0.5 vCPU / 256MB container. Real and resource-cap-driven, not a Cypher/Bolt driver defect.

Memgraph loaded right at its memory ceiling

Being fully in-memory, Memgraph auto-caps its usable heap from the container's cgroup limit and hit repeated "memory limit exceeded" retries around 200–204MiB while loading — all succeeded, but a larger dataset would likely fail outright rather than retry through it.

Footprint (stored size / memory) isn't really measured

The Bolt-platform footprint call is a stub that never parses the JMX attributes it fetches. Only ArangoDB reports a real number, and it's 0.00MB — itself suspicious. Treat every footprint figure as "not measured," not "measured as zero."

Analysis

what the numbers mean

Query latency splits cleanly into three tiers — self-hosted in-memory (Memgraph) fastest, self-hosted disk-backed (Neo4j Community, ArangoDB) a step behind, and the two real managed clouds (CognoDB, Aura) an order of magnitude slower again, dominated by network round-trip time rather than query-engine speed. A 1-hop traversal p50 is 0.52 ms on Memgraph, 1.75–2.49 ms on ArangoDB/Neo4j Community, and 256–936 ms on Aura/CognoDB.

For latency-sensitive workloads, “managed cloud” vs. “self-hosted” matters far more than which specific managed cloud you pick.

Within the managed tier, CognoDB is consistently 3–4× slower than Aura — 1-hop p50 909.81 ms vs. 256.44 ms; aggregation p50 859.08 ms vs. 256.70 ms. Some of that gap is CognoDB's retry tax, but the ratio holds even on workloads that saw no retries at all, which points to a real underlying difference: region distance, or less compute provisioned per query on CognoDB's free c0 tier than Aura Free allocates. A follow-up measuring bare network RTT to each endpoint would separate “distance” from “platform speed” — not done here.

Ingest throughput tells nearly the opposite story. ArangoDB loaded the full 326k rows in 8.78s (14,379 nodes/sec), Memgraph in 17.62s (7,168 nodes/sec) — both dramatically ahead of CognoDB's 171.43s (737 nodes/sec) or even Aura's 40.43s (3,124 nodes/sec). Bulk loading is write-heavy and round-trip-count-dominated, so the same latency penalty that costs managed clouds on reads costs them even more on writes. An ingest-heavy workload (ETL, bulk sync) widens the self-hosted-vs-managed gap further than a read-heavy one does.

Memgraph's mixed-workload throughput is the standout number in this benchmark: 1,614–2,117 qps sustained across every concurrency level tested, 2–3× ArangoDB's 1,514–2,843 qps, and roughly two orders of magnitude past Neo4j Community's collapsed throughput under contention. Memgraph pays for that with the tightest memory margin of the three self-hosted engines — under matched, free-tier-sized caps, it trades memory headroom for raw throughput, while Neo4j Community trades throughput for memory safety. ArangoDB, notably, doesn't make that tradeoff as sharply: fast on both axes, likely because its default storage engine still persists to disk instead of holding everything in-process the way Memgraph does.

So where does CognoDB actually fit? As a real, working, Bolt/Cypher-compatible managed graph database — every workload in this benchmark ran against it successfully, with zero permanent failures once its instance was reloaded clean. Compared against Aura, the platform closest to it in category (both real managed Bolt/Cypher clouds, free tier), CognoDB is consistently the slower and less stable of the two on every metric measured here: same protocol, same client driver, same dataset, same query text, same resource-tier framing. Whether that gap matters depends on the workload — for latency-tolerant background jobs, CognoDB is a functioning Neo4j-protocol-compatible option; for anything latency-sensitive on a free tier, Aura currently measures faster and more stable on this dataset.
